## Selected work

### Evaluation against customer test data

A US regional bank needed to score models against its own test data, and that feature lived only in a legacy UI. I owned my team's part of moving the supervised workflow into the new product. It shipped in about five months, and customers used it in production.

### Customer-defined evaluation metrics

Customers could define their own evaluation metrics only through the API. I led the product integration: a UI for packages of up to 50 metrics, validation of each file as it's uploaded, and the Python API changes behind both. All three phases were built behind a feature flag; one UI fix was still in review when I left DataRobot.

</a>

## How I work

### Research before scope

I study the domain, the legacy behavior and the code before I propose scope. Then I write down what's supported, what isn't, and what's still unknown.

### Small steps that ship

I cut work into the smallest end-to-end flows a user can test and use, and release them one at a time. No big-bang launches.

### Check the whole flow

I trace the complete flow myself and confirm what I find with whoever owns the code. I don't take a colleague's assurance or an agent's report on trust.
